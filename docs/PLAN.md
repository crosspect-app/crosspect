# Crosspect — план облачной версии

Решено 10–11 ноября 2026. Здесь — что строим, из чего и в каком порядке. Как устроен нынешний код — в [`ARCHITECTURE.md`](../ARCHITECTURE.md), что форма умеет сейчас — в [`STATUS.md`](../STATUS.md), как всё должно выглядеть — в [`DESIGN.md`](DESIGN.md).

## Что хотим получить

- Проповедь хранится в облаке и правится там же, без пересылки HTML-файлов.
- Вход через Google.
- Роли: **админ**, **редактор**, **проповедник**. Проповедники видят все проповеди своей церкви (настройка пространства, можно выключить), правят только свои. Редактор видит и правит всё.
- Ссылка для оператора и кнопка «Поделиться в Telegram». PDF для оператора остаётся.
- **Пространства**: «Słowo Wiary Poznań» — первое. У пространства свои участники, роли и настройки (проповедники, переводы, слайды, таймаут замка). Другая церковь заводит своё.
- Картинки — **позже** (через Google Диск церкви и Apps Script). Пока в блоке «Картинка» — описание и «Пришлю отдельно».

## Стек

| Часть | Чем делаем | Почему |
|---|---|---|
| Сайт | GitHub Pages, без сборки | Бесплатно, всегда свежая версия по ссылке |
| Вход | Firebase Authentication (Google) | Проще всего, бесплатно |
| Данные | Cloud Firestore, тариф Spark (без карты) | Бесплатно, не засыпает, офлайн и живые обновления из коробки, транзакции для замка |
| Права | Firestore Security Rules + тесты правил в CI | Проверяет сама база, а не интерфейс |
| Картинки (позже) | Apps Script от аккаунта церкви → папка на её Google Диске | Файлы принадлежат церкви, проповеднику не нужен доступ к Диску |
| Резервная копия | Ночной GitHub Action → приватный репозиторий `crosspect-backup` | Данные можно восстановить, если что-то сломается |

Firebase SDK подключается модулем с CDN (gstatic), без npm и сборки. Это единственная сторонняя библиотека сайта. Правила, их тесты и служебные скрипты лежат в `cloud/` (там npm есть, на сайт не попадает).

Отвергнуто: Supabase (засыпает через неделю простоя), Cloudflare Workers (права пришлось бы писать самим), Apps Script как основа (медленно, права обходными путями), церковный сервер (за VPN, проповедники не достанут).

## Модель данных

Утверждена на этапе 4, дополнена на этапе 8 (админы всей формы, сводки). Права проверяет сама база: [`cloud/firestore.rules`](../cloud/firestore.rules), тесты — [`cloud/tests/rules.test.mjs`](../cloud/tests/rules.test.mjs).

```

spaces/{spaceId}                         id выдаёт база (случайный)
  name, settings { lockMinutes: 10, preachersSeeAll: true, … позже: preachers, slides, translations },
  createdAt, createdBy, updatedAt, updatedBy
spaces/{spaceId}/members/{email}         email — почта Google строчными буквами
  email, role: 'editor' | 'preacher' (старое 'admin' — как editor), firstName, lastName, addedBy, addedAt
spaces/{spaceId}/sermons/{sermonId}
  v: 2, meta { title, date, firstName, lastName }, settings { … }, blocks [ … ]   ← как в файле .json
  status: 'draft' | 'submitted' | 'work' | 'done'
  owner — почта проповедника ('' — гость без входа), createdBy, createdAt, updatedAt, updatedBy
  lock: null | { email, name, at, beat }, shareKey: null | строка
  deletedAt, deletedBy — только у проповеди в корзине (этап 9.1): когда (время сервера) и кто убрал
spaces/{spaceId}/summaries/{sermonId}    сводка для списка на главной (этап 8), пишется вместе с проповедью:
  title, date, firstName, lastName, status, owner, updatedAt, updatedBy, lock, slides, refs (+ deletedAt, deletedBy — как у проповеди)
spaces/{spaceId}/sermons/{sermonId}/editor/state
  flags { blockId: {…} }, updatedAt, updatedBy           ← отметки редактора, проповедник не видит
```

Статусы (с этапа 7.3): `draft` «Черновик» → `submitted` «Готов к вёрстке» → `work` «У редактора». Старое `done` (этап 4) считается «У редактора».

Кто что может (с этапа 8 админ — один на всю форму, `admins/{почта}`; в каждом пространстве он может всё, что редактор, и ещё название, настройки и участников):

| | Админ | Редактор | Автор (`preacher`) | Без входа |
|---|---|---|---|---|
| Все пространства: список | ✓ | — | — | — |
| Пространство: читать | ✓ (любое) | ✓ | ✓ | — |
| Пространство: название и настройки | ✓ | — | — | — |
| Участники: видеть список | ✓ | ✓ | ✓ | — |
| Участники: добавлять, менять роль, удалять | ✓ | — | — | — |
| Своё имя и фамилию | ✓ | ✓ | ✓ | — |
| Проповеди: видеть | все | все | все, если `preachersSeeAll`, иначе свои | — |
| Проповеди: заводить | для любого и для гостя | для любого и для гостя | только свою, статус «Черновик» или «Готов к вёрстке» | — |
| Проповеди: править | все | все | свои, пока они не «У редактора»; статус только «Черновик» / «Готов к вёрстке»; отдать другому нельзя | — |
| Проповеди: в корзину, из корзины, стереть насовсем (этап 9.1; стереть — только из корзины) | все | все | свой «Черновик» | — |
| Отметки редактора | ✓ | ✓ | — | — |
| Сводки для списка: читать | все | все | как проповеди | — |
| Сводки: писать | только вместе с проповедью и совпадающие с ней | так же | так же | — |
| Ссылка для оператора: создать, обновить, удалить | ✓ | ✓ | для своей проповеди | — |
| Ссылка для оператора: открыть по ключу | ✓ | ✓ | ✓ | ✓ |

- Почта должна быть подтверждена (у входа через Google так всегда); регистр букв не важен.
- Время (`createdAt`, `updatedAt`, замок) ставит сервер, подделать нельзя. Кто создал — не меняется.
- Пространства и админов заводит и удаляет только служебный скрипт `cloud/scripts/admin.mjs` (из приватного репозитория). Так чужие люди не займут место в бесплатной базе церкви. Открыть заведение пространств другим церквям — одно правило, когда понадобится. С этапа 10 админ будет заводить пространства в форме (тогда — правило `create` для `isAdmin()`).
- Роли `admin` у участника нет (этап 8, перенос — `admin.mjs migrate-8`): админ всей формы не обязан быть участником пространства.

## Замок

Правила базы (этап 4) уже знают замок: под чужим живым замком никто не правит и не удаляет проповедь; замок живёт `lockMinutes` после последнего сигнала `beat`; редактор забирает чужой замок отдельной записью, без правок; свой истёкший замок можно продолжать, чужой истёкший — только забрать или снять. Остальное — в форме, сделано на этапе 6 (`js/lock.js`, подробно — `ARCHITECTURE.md`, «Замок и автосохранение»):

- «Редактировать» берёт замок транзакцией. Остальные видят «Сейчас правит Иван (с 15:20)» и проповедь только для чтения, обновляемую вживую.
- Пока правишь — автосохранение каждые несколько секунд, сигнал «я здесь» раз в минуту.
- «Сохранить» (до 7.2 — «Сохранить и закрыть») отпускает замок. Без действий дольше `lockMinutes` (по умолчанию 10, настройка пространства) — форма сохраняет и отпускает сама; если вкладку закрыли — замок истекает по последнему сигналу.
- Редактор может забрать правку принудительно.
- Пропала сеть — правки копятся в браузере и уходят при восстановлении. Если замок за это время забрал другой — сохраняются отдельной копией, чужие правки не затираются. Если другой уже закончил и отпустил замок, а проповедь изменилась — форма спрашивает, чью версию оставить (как на этапе 5).
- Отметки «доработать» — вне замка, редактор ставит их в любой момент.

## Этапы и модели

Opus — где ошибка дорогая (модель данных, права, замок). Sonnet — основная работа. Haiku — мелочи: тексты, `STATUS.md`, мелкие исправления (усилие низкое).

Усилие — сколько модель думает перед ответом. Максимальное — только где ошибка дорогая (права, замок): оно медленнее и быстрее тратит лимит.

Каждый этап — отдельная беседа в проекте claude.ai «[SWP] Crosspect». Начать беседу так (подставить номер):

> Crosspect, этап N по docs/PLAN.md. Начни со STATUS.md.

В конце этапа Claude обновляет `STATUS.md` (раздел «Этапы» — отметка и что дальше), коммитит и в последнем ответе пишет Виталию: следующий этап, модель, усилие и фразу для новой беседы. Следующая беседа продолжает с этого места.

| # | Этап | Модель | Усилие | Что получится | Нужен Виталий |
