# Crosspect — устройство

## Стек
- Сайт без сборки: [`index.html`](index.html), [`css/style.css`](css/style.css) и модули [`js/*.js`](js). Сторонних библиотек нет. Облако (правила Firestore, тесты, скрипты) — отдельно в [`cloud/`](cloud), см. «Облако».
- Модули — обычные скрипты (не ES-модули): все они делят одну область видимости, как раньше делили один файл. Порядок подключения — в `index.html`, он же порядок выполнения. Функции можно вызывать откуда угодно, но на самом верху файла нельзя использовать то, что объявлено в файле ниже по списку: например, `onclick:saveFile` не сработает, а `onclick:() => saveFile()` сработает.
- К каждому файлу в `index.html` дописано `?v=__BUILD__`: при выпуске CI подставляет номер коммита, и браузер не смешивает старые и новые файлы.
- Шрифты Google Fonts: Unbounded (переменная толщина 200–900), Inter, Noto Sans Hebrew.
- Тексты Библии — XML (Beblia или Zefania), грузятся по требованию с GitHub.
- Настройки — [`data/config.json`](data/config.json) из этого репозитория (`CONFIG_URL_DEFAULT`, ссылку сменить нельзя: окно «Источник настроек» убрано на этапе 7.3): переводы и авторы; последняя копия кешируется в localStorage; при недоступности — встроенные списки. **Настройки слайдов** (поля, шрифты, размеры, расстояния, лимиты, вид стихов, фон) — общие для пространства, в облаке (`spaces/{s}/config/slides`), см. «Настройки слайдов» ниже.
- Экраны: главная (`#`) и проповедь (`#s=<id>`, «Текст» — `#s=<id>&v=text`). «Назад» в браузере и перезагрузка возвращают туда же. Тёмные — главная и «Слайды», светлый — «Текст» (`body.light`).
- Хранение (с этапа 8 — только облако): проповеди — в Firestore; у каждой открытой проповеди есть ещё черновик в localStorage (`swp-sermon:<id>`, `swp-sermon:last` — последняя): там ждут несохранённые правки. «⋯ → Скачать файл» — копия `.json` на компьютер; открыть файл в форме нельзя. Последнее пространство — `swp-space`, копия его настроек слайдов — `swp-slides-cache:<id>`.

## Модель проповеди
Файл проповеди (`.json`) — это сам `state`:
```
state = { app:'swp-sermon', v:2, id, createdAt, updatedAt, savedAt,
  meta:{ title, date, firstName, lastName }, settings:{ lang }, blocks:[…] }
```
Блоки — слайды по порядку и заметки оператору между ними. Общее: `id, type, collapsed`. У слайдов (`TYPES[type].slide`) ещё `todo` («доработать») и `speech` — «Текст к слайду», HTML (`sanitize`). Поля `done` («готово») больше нет: `normalize` его убирает. По типам:
- `splash`: только общие поля; название, имя и дата берутся из `meta`
- `scripture`: (вид стихов — общий, в настройках слайдов) `items:[ {kind:'scripture', lang, book, chapter, sel, verses:[{num,text,orig}], ref, translation} | {kind:'scripture', manual:true, mBook, mChapter, mVerses, translation, verses:[{num,text}]} | {kind:'text', html, align, caps} | {kind:'line'} ]`
- `thesis`: `name, nameAuto, valign, parts:[ {kind:'text', html, align, scale, caps, frame} | {kind:'line'} ]`; `text` — склейка частей (для названия и старых версий)
- `quote`: `text, author, caption, scale, caps`
- `image`: `name, mode('find'|'send'), desc`; `video`: `name, mode('link'|'send'), url, from, to, desc`; `free`: `name, desc`
- `note`: `text` (не слайд: без номера, `done`, `todo`, `speech`)

Старые поля `settings` (`minScale`, `limitThesis`, `limitQuote`) и вид стихов у слайдов Писания `normalize` с этапа 7.1 убирает: это теперь общие настройки слайдов.

Версия 1 (до 11 ноября 2026) переводится в `normalize`: блоки `text` (`text, splash`) становятся `speech` слайда перед ними, а если слайда перед ними нет или `splash:true` — новой заставкой; `meta.preacher` («Фамилия Имя») → `lastName` + `firstName`; `quote.author` «Имя Фамилия, источник» → `author` + `caption`; картинка, видео и свободный без `todo` получают `todo = !done`; новые поля Писания — значения по умолчанию.

`id` переводов в `config.json` не менять: по ним сохранённые проповеди помнят перевод.

## Слайд
- Кадр раскладывается в полном размере 1920×1080 и только масштабируется (`--s`), поэтому переносы в предпросмотре и JPEG совпадают.
- Поля — CSS-переменные `--sl-x/--sl-t/--sl-b` = 44 (отступ панели) + поле из настроек. Их и остальные переменные (`--f-main/--f-greek/--f-hebrew`, `--sc-track/--sc-lead` Писание, `--th-*` тезис, `--qt-*` цитата, `--sp-foot`) `slideEl` ставит прямо на `.sl-stage` из `slideVars(slidesCfg())`: так они попадают в JPEG и в пример окна настроек. В CSS вид слайда превращает их в `--track` / `--lead` (`.sl-content`, `.sl-box-thesis`, `.sl-box-quote`).
- Вид стихов (`slidesCfg().verses`) общий: у блока `scripture` полей `caps/flow/frame/align/valign/showTr` больше нет (`normalize` их убирает). С новой строки: слева — сетка `.sl-vlist` (номера колонкой), по центру и справа — `.sl-vstack` (номер перед стихом); рамка — на всём списке.
- «Линия» (`.sl-hr`) рисуется там, где стоит в слайде, и по краям тоже; у Писания она учитывается в свободном месте снизу.
- `letter-spacing` в em на `.sl-stage` наследуется как абсолютное значение от 16 px — фактически почти ноль; трекинг задавать на самих текстовых элементах.
- Фон (этапы 7.3 и 7.5): у слайдов проповеди — `sermonBg(state)` (через `curBg` в `slideVars`), в примере окна — формат, выбранный там (`BG_TRY`). В панели слои `.sl-glow` (прежние пятна), `.sl-bg` (картинка генератора), `.sl-grain`, `.sl-vig`. Что видно, решают переменные `--sl-bg`, `--sl-glow`, `--sl-grain`, `--sl-gsz`, `--sl-go`, `--sl-va` из `bgVars`: без настройки — прежний фон один в один. Картинка узора рисуется один раз на набор настроек (кеш `bgCache`) и как `data:` URL стоит на каждом `.sl-stage`, поэтому лента не размывает заново, а JPEG получает ту же картинку. Случайность — только от `seed`, зерно — `seededRandom` с постоянным зерном.
- JPEG: слайд раскладывается в скрытом контейнере тем же кодом, клонируется вместе с CSS-правилами `.sl*` и шрифтами в SVG foreignObject и рисуется в canvas. Поэтому классы режимов вешаются на `.sl-stage`, а не на `.sl`.

## Облако в форме
- Порядок запуска: `main.js` рисует экран (пока облако подключается — «Подключаюсь к облаку…»), потом `initCloud()`: SDK `firebasejs/13.1.0` с gstatic (`firebase-app/auth/firestore`) + `cloud-api.mjs?v=<сборка>` динамическим `import()`; номер сборки берётся из адреса самого `cloud.js`. Версия SDK на CDN — `FIREBASE_VERSION` в `cloud.js`; в `cloud/package.json` SDK для тестов может быть новее.
- Firestore подключён с постоянным кешем в браузере (`persistentLocalCache`, несколько вкладок): список и открытые проповеди читаются и без сети, но **записать** без сети нельзя (сохранение — транзакция).
- Метки облака в проповеди формы: `cloudSpace`, `cloudAt` (версия в облаке, мс, на которой основаны правки; 0 — ещё не в облаке), `cloudOwner`, `cloudStatus`, `cloudBy`, `cloudShare` (ключ ссылки для оператора, этап 9; пусто — ссылки нет). Хранятся в черновике, `normalize` их сохраняет, в `.json` файл не идут (`stripCloud`). Новая проповедь и копии (`saveAsCopy`, `rescueCopy`) сразу получают `cloudSpace`, чтобы до первой записи их было видно на главной своего пространства. Конфликт — когда версия в облаке отличается от `cloudAt`.
- `isDirty()` для облака — прежнее правило (`updatedAt > savedAt`); после сохранения `savedAt` равен `updatedAt` на момент отправки, а `change()` не даёт `updatedAt` идти назад.
- Главная (`cloudItems`): строки из `cloud.list`; если в браузере есть несохранённый черновик той же проповеди этого пространства — он; несохранённые черновики этого пространства, которых в списке нет (новая проповедь без сети, копия) — тоже. Черновики без `cloudSpace` (до облака) не показываются. Чистые копии облачных проповедей из браузера убираются сами (откроются из облака).

### Админ, пространства и сводки (этап 8)
- **Админ всей формы** — документ `admins/{почта}` (поля `email`, `addedAt`). Читает только сам человек (форма спрашивает `isAdmin`), пишет только служебный скрипт (`admin.mjs set-admin` / `remove-admin`). В правилах `isAdmin()`; `isMember(s)` и `isEditor(s)` включают админа, `list` всех пространств и запись участников (`create` / `update` / `delete`) — только ему. Роль участника — `editor` или `preacher`; старая `admin` (до этапа 8) правилами читается как редактор, новая не записывается.
- `cloud-api.mjs`: `isAdmin(почта)` (нет прав — `false`), `allSpaces()` (только админу), `spacesOf` — как раньше (через участников). Админ, не состоящий в пространстве, видит его через `allSpaces`; `cloud.member` у него тогда `null` (имя для замка — из аккаунта Google).
- **Переключатель пространств**: `cloud.spaces` отсортированы по названию; при входе — пространство из ссылки (`sp`), иначе `swp-space`, иначе первое. `switchSpace(id)`: `endCloud()` (сохранить и отпустить правку), остановить слушатели, `useSpace` (роль, настройки, копия настроек слайдов `swp-slides-cache:<id>`), запустить слушатели, на главную. `route` переключает сам, если в адресе другое `sp`; пространство, куда нет доступа, — на главную с подсказкой.
- **Сводки**: `spaces/{s}/summaries/{id}` = `summaryOf(проповедь после записи)` (`cloud-api.mjs`): `title`, `date`, `firstName`, `lastName`, `status`, `owner`, `updatedAt`, `updatedBy`, `lock`, `slides` (слайды без заметок и заставок, до 500; заставки не считаются с этапа 7.7), `refs` (места Писания через « · », до 2000 знаков). Пишется в той же транзакции или пачке, что и проповедь: `save` (обе ветки), `lock`, `beat` (с этапа 8 — транзакция: прочитать, продлить, записать сводку), `release`, `setStatus`; `remove` удаляет её. Правило: сводку можно записать, только если проповедь в этой же записи изменилась (`get` ≠ `getAfter` по `updatedAt` или `lock`) и поля совпадают с ней после записи; удалить — только вместе с проповедью; читают те же, кто видит проповедь. `listen` слушает сводки; строка — `fromSummary` (`summary:true`, без `blocks`, с `slides` и `refs`). `refs` и `lock` исключены из индексов.
- Новое поле в сводке — в `summaryOf`, в `validSummary` правил (и тест), в `fromSummary`, в подмене `tests/fixtures/fake_cloud.js` (`row`); старые сводки пересчитает `admin.mjs migrate-8`.
- **Перенос `migrate-8`** (`crosspect-backup` → «Пространства»): роль `admin` у участников → `editor`, сводки для всех проповедей, лишние сводки удаляются, `--email` — назначить админа. Можно запускать повторно.
- Документ в облаке: `v`, `meta`, `settings`, `blocks` из проповеди плюс `status`, `owner`, `createdBy/At`, `updatedBy/At` (поля — как в `cloud/firestore.rules`, новое поле — сначала правило и тест). Запись — `update` только полей содержимого и замка, поэтому `status`, `owner`, `shareKey` не трогаются.

### Ссылка для оператора (`js/operator.js`, этап 9)
- **Данные**: `shares/{ключ}` = `{ spaceId, sermonId, sermon, createdBy, updatedAt }` (правила — с этапа 4: читает по ключу кто угодно, создаёт и правит тот, кто может править конспект, `createdBy` не меняется), ключ запоминается в конспекте полем `shareKey` (в форме — `cloudShare`, приходит из `fromDoc`, сохраняется через `cloudMarks`, входит в `CLOUD_FIELDS`, поэтому не попадает в «Скачать файл» и копии). `sermon` — не копия конспекта, а снимок `opSnapshot(s)`: `{ v:1, title, date, author, total, blocks:[{ t, n, … speech }, { t:'note', text }] }`, всё уже через `sanitize`; подсказок редактору (`desc`, `url`, `mode`, «доработать») в нём нет.
- **`cloud-api.mjs`**: `shareOn(space, id, me, key, snapshot, opts)` — сначала транзакция: `shareKey` + сводка, как `setStatus` (чужой живой замок — `locked`, чужой истёкший снимается), потом отдельной записью снимок; если ссылка уже есть — остаётся прежняя, снимок обновляется (нет снимка при существующем ключе — создаётся заново под тем же ключом). Снимок пишется отдельной записью, а не в транзакции с конспектом: так надёжнее при сбое. Предел правил Firestore (1000 вычислений на запрос, `PERMISSION_DENIED … maximum of 1000 expressions`) упирался не в снимок, а в обычное сохранение конспекта с `shareKey` под своим замком — правило правки проповеди и так было близко к пределу. Поэтому в `cloud/firestore.rules` проверка `shareKey` сделана дешёвой (только «строка не длиннее 64», длину 20–64 проверяет `shares/{key}`) и в правке проповеди одна проверка `isEditor` вместо двух; тест — в `cloud/tests/rules.test.mjs` («обычная правка под своим замком проходит»). Новые условия в правило проповеди добавлять осторожно: запас до предела небольшой. `shareOff(space, id, me, opts)` (с этапа 9.2 форма его не зовёт, кнопки «Отключить ссылку» нет) — сначала проверка замка, потом удаление снимка (только если он есть: удалять несуществующее правила не дают), потом транзакция: стереть `shareKey` + сводка; `shareSync(key, snapshot)` — отдельная запись `{ sermon, updatedAt }` после сохранения, её сбой сохранению не мешает; `watchShare(key, cb, onError)` — `cb({ sermon, updatedAt } | null, { fromCache })`; `remove` теперь читает конспект, и если есть снимок — сначала удаляет его отдельной записью (не удалился — конспект остаётся), потом пачка как раньше.
- **Форма**: `openOpLink` проверяет права (`canEditCloud`), сохраняет несохранённое (`saveNow` + `ed.pending`), собирает снимок и зовёт `shareOn`; `cloudWrite` (lock.js) перед отправкой собирает снимок, если ссылка есть (`s.cloudShare` или `ed.remote.cloudShare`), и после успеха зовёт `opSync` — он пропускает запись, если снимок не изменился (`opSent[ключ]`). Ключ в правке берётся из `ed.remote` (свежее, чем `state`): ссылку мог сделать или отключить другой.
- **Страница оператора**: `route()` проверяет `#op` раньше входа (`openOperator`); `initCloud` для такого адреса не запускает `onUser`/`cloudUser` (`startAuth` вызывается позже, когда уходят со страницы — `closeOperator`), поэтому лишние чтения (пространства, участники) не идут. `screen === 'op'`: шапки нет (`body[data-screen="op"] .topbar`), экран рисует `renderOperator` в `mainEl`. «Ссылка не работает» — только когда ответил сервер (`fromCache` с пустым документом — это «ещё нет ответа», например без сети).
- **Корзина (этап 9.1)**: `trash` перед пометкой удаляет снимок (как `remove`), ключ остаётся; `restore` его не трогает — форма пересобирает снимок сама (`trashShareBack` в `trash.js`).
- **Тесты**: `tests/test_stage9.py` (подмена `fake_cloud.js`: `db.shares`, `shareOn/shareOff/shareSync/watchShare`, событие `storage` будит слушателей другой вкладки); слой облака — последний `describe` в `cloud/tests/client.test.mjs` (эмулятор, только в CI).

### Корзина (`js/trash.js`, этап 9.1)
- **Данные**: у проповеди в корзине поля `deletedAt` (время сервера) и `deletedBy` (почта); у остальных этих полей нет совсем. Сводка получает те же поля (`summaryOf` копирует их, только если они есть), строка списка (`fromSummary`) и проповедь (`fromDoc`) — `deletedAt` в мс (0 — не в корзине) и `deletedBy`. Отдельной коллекции нет: главная по-прежнему слушает все сводки (`listen`) и делит их сама — `cloudItems` пропускает `inTrash`, окно «Корзина» берёт только их. Лишних чтений нет.
- **`cloud-api.mjs`**: `trash(space, id, me, { minutes })` — сначала проверка замка (чужой живой — `locked`), удаление снимка для оператора отдельной записью, потом транзакция: `deletedAt: serverTimestamp()`, `deletedBy`, `lock: null` (если был) + сводка; уже в корзине — ничего. `restore(space, id)` — транзакция: `deleteField()` у обеих пометок + сводка без них; возвращает проповедь (`readBack` до исчезновения пометки). `remove` — как раньше, но правила пускают только из корзины. `save` и `lock` у проповеди в корзине — ошибка `trashed` (новая проповедь с тем же id — тоже `trashed`, а не `conflict`).
- **Правила** (`cloud/firestore.rules`, `match /sermons/{id}`): `trashMove()` стоит первым в `allow update` — меняются только `deletedAt`, `deletedBy`, `lock`, и `deletedAt` обязательно меняется (сигнал и отпускание замка сюда не попадают); кто — `canTrash` (редактор и админ — любой, автор — свой `draft`); замок после записи — `null`; в корзину — время сервера, `deletedBy == me()`, не под чужим живым замком; обратно — обе пометки уходят. Обычная правка проповеди в корзине невозможна: `validSermon` не знает этих полей, а `canEdit` автора ещё и проверяет `!('deletedAt' in d)` (иначе автор снял бы пометку обычной правкой там, где «Восстановить» ему не положено). `allow delete` — только при `deletedAt` и `canTrash`. Сводка: `validSummary` сверяет обе пометки с проповедью, `sermonWritten` учитывает смену `deletedAt`. Тесты: `rules.test.mjs` — «проповеди: удаление насовсем», «корзина (этап 9.1)», сводка с пометками; предел в 1000 вычислений — по-прежнему проверяет «обычная правка под своим замком проходит».
- **Форма**: `trash.js` (см. таблицу файлов). Открытый конспект убрали в корзину — `onRemote` (lock.js) видит `deletedAt` (не из кеша) и зовёт `trashedAway`: на главную, несохранённое в правке — копией (`rescueCopy`). Ошибка `trashed` при записи (`cloudWrite`) и при взятии замка (`startEdit`) ведут туда же. Ссылка `#s=<id>` на конспект в корзине: `openCloudSermon` отвечает `{ missing, trashed }`, `route` — на главную, «Этот конспект в корзине» и кнопка «Корзина».
- **Автоочистка**: `cloud/scripts/admin.mjs purge-trash [--days 30] [--dry-run]` — по всем пространствам запрос `deletedAt < сейчас − дни`, для каждого: снимок для оператора, отметки редактора, сводка, проповедь. Ночью — последний шаг workflow «Резервная копия» в `crosspect-backup` (после копии: в истории копий стёртое остаётся). Тест — `scripts.test.mjs`.
- **Подмена облака** (`tests/fixtures/fake_cloud.js`): `trash`, `restore`, `remove` только из корзины, `trashed` у `save` и `lock`; в строках и проповедях — `deletedAt`, `deletedBy`.

### Работа редактора (`js/editor.js`, этап 7)
- **Статус** (этап 7.3). В облаке `status`: `draft` = «Черновик», `submitted` = «Готов к вёрстке», `work` = «У редактора» (`done` из старых данных — тоже «У редактора», `statusKey`). Форма держит его в `state.cloudStatus`, `cloudWrite` отправляет `status` вместе с содержимым. Переключатель (`statusSwitch`) меняет статус только в правке: `setSermonStatus` ставит `cloudStatus`, двигает `updatedAt` и зовёт `onEdit()` (как `change()`, но без `histRecord`), так что статус уходит с автосохранением или по «Сохранить» и правку не закрывает. Автосброса при правке автора больше нет. «У редактора» (`work`) автору недоступно; пока он стоит, `canEditCloud()` для автора — `false` (права проверяются по облачной версии, в `beginCloud` — по `remote`): «Редактировать» неактивна с подписью `AT_EDITOR_MSG`, щелчок по полям — та же подсказка, несохранённые правки из браузера уходят копией (`rescueAndShow`). Правило: `canEdit` в `cloud/firestore.rules` не пускает автора править, брать замок, менять статус и удалять при `work` / `done`; тесты — `rules.test.mjs` («У редактора»), `client.test.mjs`. `closeEdit` возвращает `'ok'` или причину.
- **«Доработать» в облаке** не лежит в проповеди: `cloud-api.mjs` вырезает `todo` и `done` из блоков при записи. Отметки — `spaces/…/sermons/<id>/editor/state`, `flags: { <id слайда>: { t: 1 | 0, s: подпись } }`; читает и пишет только редактор и админ, замок не нужен (так сделаны правила этапа 4). Показ: `applyFlags` накладывает отметки на `state.blocks[].todo` (вызывается в `openCloudSermon`, `setRemoteState`, `takeRemote`); записи нет — картинка, видео и свободный слайд «доработать» (`TYPES[type].todo`), остальные нет. `s` — `blockSig(b)`: канонический JSON блока без `todo`, `done`, `collapsed`; `t = 0` и подпись не совпала → отметка вернулась (считается при показе). `resyncFlags` после сохранения обновляет `s` у слайдов без отметки, чтобы собственные правки редактора её не возвращали. Запись — `flushFlags` с паузой, набор целиком; пока проповеди в облаке нет (`cloudAt` = 0), ждёт.
- Спикеру отметки не читаются (`getFlags` отдаёт `{}`), `canFlag()` = `false`: интерфейс (`todoOn`, кнопка, блок «Для редактора», счётчик) их не показывает. Без входа `toggleTodo` работает как раньше — правит проповедь через `change()`.
- Фильтр «только отмеченные» — `filmOnlyTodo` в `slides.js`, переключается щелчком по счётчику над лентой.
- Запас базы: код ошибки `resource-exhausted` — `ed.quota`, правки остаются в черновике браузера, повтор раз в `QUOTA_RETRY_MS` (5 минут), Ctrl+S — сразу; текст «Облако перегружено до 9:00» — в `explain`. Автосохранение — `AUTOSAVE_MS` (30 с); тесты сокращают его через `window.CROSSPECT_AUTOSAVE_MS` (подмена облака ставит 3 с).

### Замок и автосохранение (`js/lock.js`, этап 6)
- Замок в документе: `lock = { email, name, at, beat }`, время ставит сервер. «Свой» замок — почта **и** `at` (запоминается на вкладку в `sessionStorage swp-lock:<id>`): другая вкладка той же почты берёт замок заново с новым `at`, и прежняя вкладка понимает, что замок ушёл. После перезагрузки замок берётся заново (`force`), черновик перебазируется на свои же записи (`ownSince`).
- Режимы: `ed.mode` = `view` (по умолчанию для облачной проповеди) или `edit`. `readOnly()` — просмотр: `change()` откатывает правку (`roBlock`) и показывает подсказку; правая панель, «Текст к слайду» и текст в виде «Текст» — `inert`; черновик в браузере не пишется (`persistDraft` пропускает), чтобы не затереть черновик другой вкладки.
- Правка: `change()` → `onEdit()` → запись через 30 с (`AUTOSAVE_MS`, не чаще одной записи одновременно). `cloudWrite` → `api.save(..., { lock:{ name, at, release, minutes } })`: под своим замком запись продлевает `beat`, без замка (или с истёкшим чужим) — берёт новый, с живым чужим — `lost-lock`. Пока замок свой, свои же записи с более новой версией (дошедшие после обрыва связи) конфликтом не считаются (`ownLater` в транзакции).
- `tick` раз в 15 с: сигнал `beat` раз в минуту (только если человек что-то делал), простой ≥ `lockMinutes` — `closeEdit('idle')`; в просмотре — обновить шапку (чужой замок мог истечь). Активность — `pointerdown` / `keydown` / `wheel`.
- `watch` (onSnapshot документа): в просмотре — новая версия сразу на экран (`setRemoteState`, прокрутка сохраняется); в правке — только замок: чужой с `at` позже моего — `lostLock` (несохранённое — `rescueCopy`, окно «Правку забрали»).
- Уход с проповеди (`route`, «Новая», смена пространства, «Выйти») — `endCloud()`: сохранить и отпустить фоном. Скрыли вкладку — записать сразу; закрывают вкладку с несохранённым — браузер спрашивает «Покинуть сайт?».
- Без сети запись (транзакция) не проходит: `ed.offline`, правка ждёт в черновике, повтор через 15 с и по событию `online`. Начать правку без сети нельзя.

### Анимации (`js/motion.js`, этап 7.6)
- Длительности — переменные `--motion-fast` 120 / `--motion` 200 / `--motion-slow` 250 мс и `--ease-out`; анимируются только `transform` и `opacity` (у переключателя статуса ещё цвет). CSS и Web Animations API, библиотек нет.
- `prefers-reduced-motion: reduce`: в CSS переменные 0 мс и общий нулевой переход, в JS `MOTION.off()`. Исключения: переходы знака (`.lg-*`, анимация сохранения) и подсветка `.hl` (остаётся без сдвигов). Зерно входа, фон главной и блик заглушек стоят.
- Выгрузка: `exportOne` / `exportMany` вызывают `motionPause()` после `exporting = true` и `motionResume()` в `finally`; класс `html.no-motion` гасит анимации и переходы (кроме `path`), живые анимации завершаются.
- Скрытая вкладка: класс `html.page-hidden` ставит бесконечные анимации на паузу.
- Перерисовка ленты (`addBlock`, `move`, `moveTo`, `duplicate`, `removeBlock`, `histApply`) обёрнута в `motionFilm`: снимок прямоугольников до (как видно на экране, со сдвигами перетаскивания), FLIP после. С этапа 7.7 узлы те же, поэтому движение идёт на живых миниатюрах; незаконченный FLIP прошлого действия отменяется после снимка. Длительность — `--motion-slow`. «Слайды ↔ Текст» — `viewTransition` в `showSermon`. Галочка и замок — в `renderTopbar` (`motionBeforeTopbar` / `motionAfterTopbar`). Автосохранение не гоняет знак: `cloudWrite` использует `logoTo` только при `o.manual` или если знак уже не в покое; иначе `motionCheck()`.
- Уведомления — стопка `.toasts` (`toast()` в `misc.js`), не больше 4, одинаковые не плодятся.
- Тесты: `tests/test_ui76.py`; `cloud_page(..., reduced_motion="reduce")` по умолчанию, тесты движения передают `"no-preference"`.

### Лента без пересборки (этап 7.7)

- Объекты блоков после отмены и обновления из облака новые, узлы старые: обработчики ленты берут блок по id (`blockById`); панель и «Текст к слайду» с замыканиями на блок пересобираются.

- Открытие проповеди: `openCloudSermon` экран не трогает (раньше рисовал «Открываю проповедь…»), `route` ждёт данные, `slideAssetsReady` (шрифты Unbounded 325/700/900 и Inter, не дольше 1,2 с) и `bgReady` (`img.decode()` картинки фона, не дольше 0,4 с).

## Облако (`cloud/`)
Firebase: Cloud Firestore + вход Google. Что строим и по каким этапам — [`docs/PLAN.md`](docs/PLAN.md), там же модель данных и таблица прав. Настройка проекта — [`docs/FIREBASE.md`](docs/FIREBASE.md). Форма подключена к облаку с этапа 5: см. «Облако в форме» ниже.

| Файл | Что внутри |
|---|---|
| `cloud/firestore.rules` | права: админы всей формы (`admins`), пространства, участники, сводки (`summaries`), настройки слайдов (`config/slides`), проповеди, замок, отметки редактора, раскладка экрана человека (`people/{почта}/prefs/screen`), ссылки для оператора. Функции наверху (`signedIn`, `me`, `hasRole`, `isEditor`…), затем `match` по коллекциям |
| `cloud/firestore.indexes.json` | индекс `members.email` для запроса по всем пространствам (collection group); тяжёлые поля (`blocks`, `settings`, `flags`, `sermon`) исключены из индексов |
| `cloud/firebase.json` | пути к правилам и индексам, порт эмулятора |
| `cloud/tests/rules.test.mjs` | тесты правил в эмуляторе (`node:test` + `@firebase/rules-unit-testing`): вход, пространство, участники, чтение / создание / правка / удаление проповедей, замок, отметки, ссылки. `RULES_FILE=путь` — прогнать на другом файле правил |
| `cloud/tests/scripts.test.mjs` | служебные скрипты в эмуляторе: пространство и участники (и что их записи проходят правила), бэкап → очистка → восстановление даёт ту же копию |
| `cloud/scripts/lib.mjs` | подключение (эмулятор или ключ `GOOGLE_APPLICATION_CREDENTIALS`), перевод документов в JSON (`$timestamp`, `$ref`, `$map` …) и обратно |
| `cloud/scripts/backup.mjs` | вся база в папку: документ → `путь/документа.json` |
| `cloud/scripts/restore.mjs` | папка → база, `--wipe` сначала очищает |
| `cloud/scripts/admin.mjs` | `create-space`, `set-member`, `remove-member`, `set-admin`, `remove-admin`, `migrate-8`, `purge-trash` (корзина, этап 9.1), `list` — в обход правил; сводки считает `summaryOf` из `js/cloud-api.mjs` |
| `cloud/private-repo/` | файлы для приватного репозитория `crosspect-app/crosspect-backup`: ночная копия (и уборка корзины после неё, этап 9.1), восстановление, «Пространства». Меняешь здесь — перенеси туда |

- `cloud/tests/client.test.mjs` — код `js/cloud-api.mjs` в эмуляторах Firestore и Auth (вход выдуманной учёткой Google, настоящие правила): членство, создание и обновление, конфликт версий, права проповедника, закрытое пространство, живой список, удаление; замок: новая проповедь с замком, продление и отпускание записью, взять / сигнал / отпустить, «занято», редактор забирает, `lost-lock`, другая вкладка той же почты, свои записи после обрыва связи, истёкший чужой замок, `watch`; настройки слайдов и форматы фона (пишут админ и редактор, автор — нет; данные 7.3 с `bg`).
- Тесты: `cd cloud && npm ci && npm test` (Node 22, Java 21; эмулятор Firestore скачивается с Google Storage — в рабочей среде Claude он закрыт, поэтому тесты правил гоняются в CI: запушить ветку и запустить workflow вручную, `gh api -X POST repos/crosspect-app/crosspect/actions/workflows/ci.yml/dispatches -f ref=<ветка>`).
- Секрет `FIREBASE_SERVICE_ACCOUNT` (JSON-ключ сервисного аккаунта с ролью Firebase Admin) — в обоих репозиториях. Идентификатор проекта берётся из ключа (`project_id`).
- Email в базе — всегда строчными; `me()` в правилах приводит почту из токена к строчным.
- Время — только `serverTimestamp()`: правила сверяют его с `request.time`.
- Новое поле проповеди — добавить в `validSermon` (`hasOnly`) и тест; иначе база его не примет.

## Выпуск
Файл `.github/workflows/ci.yml`: на каждый коммит идут тесты формы (`Тесты`) и правил (`Правила Firestore`); если коммит в `main` и всё прошло, сайт (`index.html`, `css`, `js`, `data`) выкладывается на GitHub Pages, а правила и индексы — в Firebase (`Выкладка правил Firestore`; без секрета `FIREBASE_SERVICE_ACCOUNT` шаг пропускается). Адрес: `https://crosspect-app.github.io/crosspect/`. В Settings → Pages источник должен быть «GitHub Actions».
