# Правила для Claude в репозитории Crosspect

- Сначала прочитай `STATUS.md` (что есть и что дальше) и `ARCHITECTURE.md` (как устроен код): `ARCHITECTURE.md` — оглавление, части в `docs/arch/` читать только нужными разделами (`grep -n '^#' docs/arch/X.md`, потом диапазон строк).
- Пользователь — Виталий, не программист. Код пишет Claude. Решения по продукту и текстам — за Виталием: перед изменением поведения или текстов, которые увидят проповедники, согласовать.
- Работа идёт по этапам из `docs/PLAN.md`; в начале беседы найди в `STATUS.md` текущий этап, в конце — отметь его и коммить. Модель и усилие для этапа указаны в плане: если беседа идёт на другой модели, скажи об этом Виталию в первом ответе. В последнем ответе этапа обязательно напиши, что делать дальше: номер следующего этапа, какую модель и какое усилие выбрать, и фразу для новой беседы.
- Форма — `index.html` + `css/style.css` + `js/*.js`, без сборки; обычные скрипты в общей области видимости (не ES-модули), порядок подключения задан в `index.html`. Сторонних библиотек нет; позже добавится только Firebase SDK с CDN.
- Новый файл в `js/` нужно подключить в `index.html` с `?v=__BUILD__`; в верхнем уровне файла нельзя передавать функцию из более позднего файла по имени (`onclick:foo`) — писать `() => foo()`.
- Старые файлы проповедей должны открываться: любые изменения модели — через `normalize` / `normItem`.
- Перед коммитом запускать тесты: `python3 -m pytest tests -q` (редактор, файлы, просмотр, JPEG, ZIP, PDF). Новое поведение — новый тест в `tests/`. Подробности — в `docs/arch/tests.md`.
- Облако — `cloud/` (правила Firestore, их тесты, бэкап, скрипты пространств). Любая правка `cloud/firestore.rules` — только с тестом в `cloud/tests/rules.test.mjs`, и тесты должны пройти в CI до слияния в `main` (из `main` правила сразу уходят в боевую базу). Эмулятор в рабочей среде Claude не скачивается: ветка → ручной запуск workflow → логи (см. `docs/arch/cloud.md`).
- Ключ сервисного аккаунта — только в секретах GitHub; почты участников не выводить в логи публичного репозитория (служебные действия — из приватного `crosspect-backup`).
- Если Виталий вставляет код сам — присылать файл целиком, не фрагменты.
- Тексты для пользователей — естественный русский, без канцелярита и кальки; каждое утверждение — правда.
- Документы (карта — в `STATUS.md`): `STATUS.md` переписывать, а не дописывать — только текущий этап, готовые этапы одной строкой и что дальше; бюджет 12 000 байт. Что умеет форма — `docs/FEATURES.md`; записи по этапам — `docs/HISTORY.md` (новые сверху); решения и предпочтения — `docs/DECISIONS.md`; что делает Виталий для приёмки — `docs/CHECKS.md`; отметка этапа и отложенное — `docs/PLAN.md`. Бюджеты проверяет `tests/test_docs_budget.py` (CLAUDE.md ≤ 6 000 байт).
- Телефон (этап 10.1.1): фон главной на телефоне — картинка `img/wall-phone.webp`. Сменился стандартный фон, шрифт названий или `WALL_TITLES` — переснять `python3 tools/wall_image.py` и закоммитить (`docs/arch/phone.md`). На компьютере вид менять нельзя: правки узкого экрана — только в блоке «Телефон» в конце `css/style.css`.
- Инструкция «Как пользоваться» (страница `#help`, наполняется на этапе 12): при каждом изменении или добавлении функциональности поправить и её (текст и скриншоты). Инструкция — на «ты», для авторов; интерфейс формы — на «вы».
- «Конспект» — документ в форме (список «Конспекты», «Новый конспект», «Удалить конспект»), «проповедь» — само событие («О проповеди», «Название проповеди», «Заставка проповеди»).
- Коммиты на русском, коротко, что изменилось для пользователя.
